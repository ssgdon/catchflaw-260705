# 캐치플로 리뷰 판정 검증 기준 (Opus 재검증용)

캐치플로는 호텔 리뷰를 LLM(분류 v5.7)으로 판정해 "실망 확률"과 항목별 불만을 보여준다.
한 리뷰에서 여러 판정이 나올 수 있다(리뷰 1개 → 판정 N개). 각 판정 = (대분류 cat, 소분류 sub, 등급 grade, 근거 인용 quote).
너는 판정 하나하나가 맞는지 검증한다. 여기 있는 판정은 전부 등급이 '심각' 또는 '주의'(= 불만으로 셈)인 것이다.

## 등급
- **심각**: 숙박을 망치거나 예약을 후회하게 만드는 수준. 위생·건강·안전 문제(살아있는 벌레·빈대, 눈에 띄는 곰팡이, 무단 입실), 잠을 못 잘 정도의 소음, 필수 기능 불능(온수 안 나옴, 에어컨 고장으로 견딜 수 없음), 방 변경·환불 요구로 이어진 문제, 강한 분노 표현.
- **주의**: 눈에 띄는 불편이지만 숙박을 망치지는 않은 정도("조금 좁다", "약간 시끄러웠다", "직원이 무뚝뚝").
- 등급은 경계가 애매한 경우가 많다. **명백히 틀린 경우만** 고친다(예: "방이 조금 좁았지만 만족" → 심각은 과함 / "바퀴벌레가 침대에 있었다" → 주의는 부족).

## 검증 절차 (판정마다)
1. **불만인가?** quote와 원문(text, 비한국어는 tr 번역 참고)을 읽고, 이 소분류에 대해 투숙객이 실제로 불만을 말했는지 본다. 칭찬·중립·부정문("벌레 없음")·기대만 언급·다른 호텔 이야기·가정이면 `not_complaint`.
2. **분류가 맞는가?** 위 표의 정의로 cat/sub를 확인한다. 같은 대분류의 다른 소분류가 맞으면 `wrong_sub`, 다른 대분류면 `wrong_cat`, 표에 없는 불만이면 `out_of_taxonomy`.
3. **등급이 명백히 틀렸나?** `grade_too_high` / `grade_too_low` (명백할 때만).
4. **인용이 근거가 되나?** quote가 해당 불만을 담지 못하고 원문 다른 부분에 근거가 있으면 `quote_mismatch`(분류 자체는 맞을 수 있음 — 이때 new_* 는 원래 값).
- 한 리뷰에 같은 불만이 이미 다른 판정으로 잡혀 있을 수 있다. 이 판정만 보고 판단한다(중복 여부는 따지지 않는다).
- 확신이 없으면 `ok`로 둔다. 고친 판정은 DB에 반영되므로 **정밀도가 재현율보다 중요하다.**

## 출력
배치 파일의 모든 판정을 검토하되, **고쳐야 하는 판정만** JSONL 한 줄씩 출력한다:
`{"id": "<id>", "issue": "not_complaint|wrong_sub|wrong_cat|out_of_taxonomy|grade_too_high|grade_too_low|quote_mismatch", "new_cat": "<대분류 또는 null>", "new_sub": "<소분류 또는 null>", "new_grade": "심각|주의|정상|null", "conf": "high|med", "why": "<한국어 한 문장, 근거 인용 포함>"}`
- not_complaint / out_of_taxonomy → new_cat/new_sub null, new_grade "정상".
- wrong_sub / wrong_cat → new_cat/new_sub 채움(표의 정확한 이름), new_grade는 원래 등급 또는 바뀐 등급.
- grade_* → new_cat/new_sub는 원래 값, new_grade만 바꿈.
- 한 판정에 문제가 둘이면 더 근본적인 것 하나(not_complaint > wrong_cat > wrong_sub > grade).

## 추가 경계 규칙 (1차 검증 후 확정, 2026-10-11)
- 어메니티: 체크인 때부터 수량 부족·종류 없음 = `out_of_taxonomy` / 연박 중 미보충(수건·휴지·쓰레기봉투 교체 안 됨) = 청소 안 됨.
- 투숙하지 않은 방문(식당·바·웨딩·연회·당일 스파만 이용) 리뷰 = `out_of_taxonomy`.
- 대욕장·욕조·객실 안 부상(미끄러짐·화상) = 안전/객실 보안('보안·안전사고'). 대욕장 시설 자체 불만(수압·온도)은 `out_of_taxonomy`.
- 계단·엘리베이터 없음·입구 턱 = 객실/낡음·고장(역 거리 아님).
- 직원: 태도(무례·무시·말 안 통함) = 불친절 / 처리 실패(잘못된 안내·요금·예약 착오·요청 미처리·연락 안 됨) = 대응 미흡 / 기다림 자체 = 대기·지연.
- 번역(tr)이 원문(text)과 다르면 원문 기준으로 판단한다.
- 벌레·곰팡이·동네 분위기·객실 보안의 **등급**은 운영자가 이미 전수 점검했다 — 이 4개 소분류의 등급 변경 제안은 `hold`로 표시(분류 변경은 평소처럼 판단).

## 운영자 결정 규칙 (2026-10-11 확정)
1. **창문**: 창문이 *없음*·창밖이 벽이라 빛이 안 듦 = 객실/좁은 방. 창문이 *안 열림*·환기 안 됨·답답함 = 객실/실내 온도(환기). 방이 넓다고 했는데 창문만 문제면 좁은 방이 아니다.
2. **습도·건조**: 습하다·건조하다·침구가 눅눅하다 = 객실/실내 온도(인정). 이유로 판정을 지우지 않는다.
3. **일행 간 사생활**: 반투명·유리 욕실, 욕실 문 없음·잠금 없음, 커튼만 있는 칸막이처럼 *같이 묵는 사람끼리* 불편한 구조 = 객실/좁은 방(객실 구조). 객실/안전 › 객실 보안은 외부인 침입·무단 입실·잠금 고장·외부로의 사생활 노출(창밖·옆방에서 보임)·부상만.
4. **투숙하지 않은 방문**: 식당·바·카페·웨딩·연회·당일 스파만 이용한 사람의 리뷰(직원 불만 포함) = 판정 없음(`out_of_taxonomy`). 투숙객이 호텔 안 식당·조식에서 겪은 직원 태도는 직원 소분류로 유지.
